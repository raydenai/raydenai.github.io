# Portfolio / IP Workflow Simulation

## Simulation purpose

This fictional Elliot Vale concept pack tested the Portfolio / Intellectual Property archetype from an empty intake through release authorization. The commercial problem was not a single offer; it was visitor routing across frameworks, ventures, advisory and media conversations. The approved human architecture was `portfolio-ip`, even though the heuristic initially ranked Private Signal at medium confidence. The assessment preserved the human decision rather than treating the heuristic as an override.

## Compiled commercial route

| Client input | Compiled result |
|---|---|
| Primary buyer | Founders, operators and institutional partners deciding between a framework, venture, advisory, or media route. |
| Core tension | A multi-venture body of work can become a fragmented accomplishment collage that forces visitors to decode the ecosystem alone. |
| Thesis | A portfolio becomes authority only when each book, venture and conversation gives a visitor a clearer route to a decision. |
| Primary conversion | **Choose the relevant route**. |
| Approved form fields | `name`, `work_email`, `organization`, `inquiry_route`, `decision_context`, `timing`. |
| Proof posture | Concept-safe authority map, method and publication standard only; no fictional books, ventures, features, clients or results. |

## Generated page system

The workflow generated six pages: Home, About, Ventures, Books and Media, Work With Me, and Contact. The home sequence is Hero → Proof → Story → Offer → Final Conversion. The visitor is first oriented to the authority map, then given a decision-relevant proof standard, an origin/context signal, a route-selection offer, and a form that asks for the relevant route rather than a generic contact message.

## Extensibility findings and corrections

The first strict release attempt correctly failed because the Portfolio / IP profile required P07 and P09 but neither was used in the generic plan. The planner was extended so P07, a public-context or presentation role, appears on proof; P09, a decision artifact or framework role, appears on offer / route-selection sections. The same compile caught an MDX fallback issue: the Build Notes packet used a generic “Explore the work” CTA even when a client had approved a more specific conversion. The MDX compiler now resolves the approved strategy conversion first, then the brief action, and finally only the archetype fallback. The regenerated Elliot packet correctly uses **“Choose the relevant route.”**

## Release result

After the two corrections, the simulated pack generated four planned photo roles, fourteen prompt packets, typed Astro candidates, a Build Notes MDX candidate, a wireframe approval pack, a zero-diagnostic design contract, and a release dossier. The release reached `release_authorized` and passed client contract, block sequence, types, images, static build, static policy, responsive visual QA and keyboard accessibility smoke testing. As a concept pack, its generated content remains non-publishable until a reviewer promotes approved JSON or MDX through the content ledger.
