# Proof Machine Production Blueprint

The selected production direction is **Proof Machine**. Its job is not to make the fictional Priya demo appear “more impressive.” Its job is to demonstrate what a real consultant website does when it treats **evidence, interpretation, and a named system** as the primary creative material.

> **Production principle:** The person appears in the work. The record leads the page.

## 1. What changes from the first demo

| First demo pattern | Proof Machine replacement | Reason |
|---|---|---|
| Cut-out portrait as the main hero event | Documentary / environmental image beside a hard evidence thesis | Makes the expert feel active in a real arena rather than placed on a template |
| Generic “premium authority” dark-and-gold language | Ink, paper, one signal blue, rule-based information system | Gives the page a more specific operator / analyst character |
| Long persuasion stack before visible proof | Receipts, system, and case evidence appear in the first two screen lengths | Lets an analytical buyer decide early whether the record is worth attention |
| Services grid | Decision paths, named outputs, and visible engagement proof | Frames the offer as an intervention, not a menu |
| Testimonials as a late social-proof block | Cases are small arguments: context → intervention → result | Turns the strongest evidence into the primary storytelling mechanism |
| Image sections as decoration | Every photo has a role: arena, work, artifact, or human signal | Prevents repetitive portrait use and creates a photo narrative |

## 2. Global shell

The production shell adopts an editorial utility bar with the brand name on the left, the active thesis / direction in the centre, and a direct action on the right. The primary navigation becomes:

| Navigation label | Route | Visitor question answered |
|---|---|---|
| `The Record` | `/about/` | Why should I trust this person’s judgment? |
| `The System` | `/method/` | What is the actual method? |
| `Case Files` | `/case-studies/` | Has this worked in a comparable context? |
| `Work Together` | `/work-with-me/` | What is the appropriate intervention? |
| `Notes` | `/blog/` | How does this person think in public? |
| `Run the Diagnostic` | `/contact/` | What should I do next? |

The global footer should become a short close-out, not a duplicate navigation dump. It presents the diagnostic, direct contact path, and one statement about evidence / permission. The existing accessible mobile drawer remains; its labels and primary action change with the new shell.

## 3. Home page order

| Order | Production module | Claim being earned | Required asset / evidence |
|---|---|---|---|
| 1 | **Evidence hero** | “The work is real, but the market cannot yet read it.” | Environmental or stage portrait; a specific non-invented positioning statement |
| 2 | **Receipt bar** | “This is a structured advisory practice, not generic coaching.” | Categories / proof types, not fake press logos |
| 3 | **Old model / better model rail** | “The current behavior creates the wrong outcome.” | Three contrarian comparisons anchored in actual buyer language |
| 4 | **Signal Stack diagram** | “There is a repeatable way through the problem.” | Named four-step method and explicit outputs |
| 5 | **Case file index** | “The method changes meaningful business conditions.” | Permissioned case data; otherwise clearly marked illustrative records |
| 6 | **Evidence ledger** | “The record can be evaluated at a glance.” | Attributed results, testimonials, association / media context |
| 7 | **Working view** | “This is the person and level of engagement behind the system.” | Workshop / desk / documentary photograph |
| 8 | **Diagnostic CTA** | “There is a concrete next step.” | Short form or booking path, expected response time |
| 9 | **Field notes** | “The thinking is ongoing and useful.” | Articles, clips, or other owned intellectual property |
| 10 | **Closing question** | “The visitor has a named decision to make.” | One action only: run the diagnostic / request a call |

## 4. Evidence policy for the demo and real clients

The current Priya implementation is a fictional demo. The fully refined page will therefore stop presenting fictional named companies, exits, media coverage, and outcomes as if they were historical fact. Production proof is categorised as follows:

| Evidence status | Treatment | Permitted use |
|---|---|---|
| `approved` | Client name, specific outcome, attribution, source / permission note | Public case cards and outcome ledger |
| `anonymized` | Sector, role, relevant scale band, and specific but non-identifying result | Confidential case cards |
| `illustrative` | Explicitly labelled “illustrative system demonstration” | System prototype only; never in public production claims |
| `unverified` | Omitted | Never publish it |

This is the important difference between a visual proof machine and a fabricated authority machine: the interface reserves the most prominent visual real estate for evidence, so it demands more discipline about what is true.

## 5. Supporting pages

| Page | Production role | Signature device |
|---|---|---|
| `/about/` | The record behind the thesis | Timeline / annotated turning point / documentary image sequence |
| `/method/` | The Signal Stack in depth | Four-layer map with input, decision, output, and evidence requirements |
| `/case-studies/` | Permissioned proof library | Filterable or sequential case files, each with a compact context / intervention / result ledger |
| `/work-with-me/` | Engagement paths | Decision path matrix: private advisory, team intervention, keynote / work session |
| `/speaking/` | Live evidence | Topic cards, stage imagery, outcomes and technical information |
| `/contact/` | Diagnostic intake | Direct inquiry form, evidence readiness prompt, real response-time promise |
| `/blog/` | Field-note library | Strong editorial index, no generic card wall |

## 6. Photo hierarchy

| Image role | Where it appears | Desired effect |
|---|---|---|
| Arena frame | Home hero / speaking | Establishes the world where the work matters |
| Documentary work | Case file and working view | Makes the method feel active and real |
| Editorial portrait | About / key conversion moment | Restores human proximity after evidence is established |
| Artifact / detail | Method, notes, photo breaks | Adds material texture and protects against portrait repetition |
| Testimonial avatar | Small, subordinate proof detail | Preserves attribution without turning proof into a UI decoration |

## 7. Implementation plan

The build will create a dedicated production page shell rather than try to approximate this system by stacking generic blocks. The existing portable block system remains intact for repeatable client implementation; the selected direction becomes an advanced **directional template** that demonstrates what happens when the block system is given a single coherent thesis.

The root page will use a specialised Proof Machine composition. The current page content collection remains the source of brand information and later becomes the source of approved cases, field notes, and conversion details. Supporting pages receive matching production-level headers, title treatments, proof rails, and direction-specific modules in the next refinement phase.
